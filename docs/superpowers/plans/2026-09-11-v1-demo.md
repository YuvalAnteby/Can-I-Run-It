# V1 Publishable Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Use `impeccable` skills for UI if needed.

**Goal:** Deliver the V1 compatibility contract, provenance-safe fallback behavior, publishable UI, reproducible Docker deployment, and verification/documentation for issues #54, #55, #56, #57, #58, #59, #60, and #47.

**Architecture:** Keep `CheckService` as the single orchestration point. Use a string provenance column in `performance_records`, explicit API source/verdict fields, one shared verdict/warning decision helper, and the existing React Query/Axios flow. Keep PostgreSQL init SQL as the schema source of truth and add only an in-process check rate-limit guard.

**Tech Stack:** NestJS 11, TypeScript, TypeORM, PostgreSQL 16, React 19, Vite, React Query, Tailwind CSS, Jest, Supertest, Vitest, React Testing Library, MSW, Docker Compose, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-09-11-v1-demo-design.md`

## Global Constraints

- Exact lookup identity is game, CPU, GPU, RAM, resolution, and settings preset; requested upscaler/upscaler quality are optional preference tie-breakers only.
- Measured rows always outrank provider rows; heuristic and ML results are never persisted.
- Target FPS accepts only `30`, `60`, `90`, `120`, or `144`; absent target FPS defaults to `60`.
- VRAM can override a positive verdict; SSD is advisory; storage capacity is not collected.
- The public API never exposes provider credentials, stack traces, or fabricated 1% low FPS values.
- Production TypeORM synchronization stays disabled; PostgreSQL init SQL and tracked seed data bootstrap fresh volumes.
- All commits use Conventional Commits and never add a co-author.
- All implementation work stays on `feat/v1-demo`; integration into `staging` happens through a pull request.
